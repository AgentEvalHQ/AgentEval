# AEF ingestion storage

AEF ingestion uses dedicated application storage. It must not write into the
Mission Control viewer's existing `.agenteval` output store or into source run
folders. `IAefIngestionWorkspace` in `AgentEval.Results.Ingestion` owns this
boundary independently of HTTP, GraphQL, or a database.

## Workspace ownership

`AefIngestionWorkspaceOptions.Root` is a required absolute path. There is no
fallback to the working directory or the viewer's workspace. The root must be
empty on first initialization. An existing initialized root must carry the
supported version marker. Filesystem roots and symbolic links/reparse points
in the path or managed layout are refused.

```csharp
using var workspace = new AefIngestionWorkspace(new()
{
    Root = "/var/lib/agenteval/ingestion",
    MaxPendingStages = 64
});
var stage = workspace.BeginStage(cancellationToken);
```

Mission Control registers this service only when `AgentEval:Ingestion:Enabled`
is `true`. Set `AgentEval:Ingestion:Root` to the dedicated absolute root and,
optionally, `AgentEval:Ingestion:MaxPendingStages`. Environment-variable names
use double underscores, for example `AgentEval__Ingestion__Enabled=true`.
Startup acquires ownership and refuses invalid configuration or roots that
overlap the viewer's `.agenteval` directory in either direction. The DI
container releases ownership when disposed. With ingestion disabled (the
default), no ingestion services are registered and no ingestion storage is
created. HTTP ingestion is a subsequent lifecycle slice.

The root contains:

| Entry | Purpose |
| --- | --- |
| `.ingestion-version` | Workspace format marker, currently version 1 |
| `.ingestion.lock` | Exclusive process lease, held until service disposal |
| `.staging/<opaque-id>/` | Incomplete imports, never accepted query evidence |
| `runs/` | Destination reserved for verified, finalized runs |

Staging identifiers are generated by the service. Callers cannot select a
destination name. Paths returned by the service are local implementation
details and must not be returned by HTTP endpoints. The configured root must
be writable only by trusted local processes. Link checks do not protect
against a privileged or same-owner process replacing files during access;
filesystem permissions are part of the storage boundary.

## Capacity and interruption

`MaxPendingStages` defaults to 64 and accepts values from 1 through 1024.
Reservations are serialized within the owner. All entries directly under
`.staging` count against capacity, including retained interrupted stages and
unexpected entries. Counting stops at the configured limit and does not walk
stage contents.

Disposal releases the exclusive lease without deleting files. Reopening the
workspace therefore preserves both staged bytes and their capacity usage.
Cancellation before reservation creates no stage. A refused initialization
releases its lease; it does not delete an existing root or evidence. Empty
initialization directories and the lease file may remain after failure.

## Bounded source discovery

`IAefRunDiscovery` finds candidate run folders under an explicitly supplied
absolute local directory. It is registered with the opt-in ingestion services.
It does not copy, parse, verify, or index evidence:

```csharp
var result = discovery.Discover(sourceRoot, new AefDiscoveryOptions
{
    MaxDepth = 8,
    MaxEntries = 10_000,
    MaxRuns = 1_000
}, cancellationToken);
```

These are the default limits. Depth counts the source root as zero and allows
0..64; entries allow 1..1,000,000; candidate count allows 1..100,000. Hidden
entries are included. A regular `run.json` marker identifies a candidate even
if its bytes are invalid JSON or no seal exists. Discovery never opens the
marker or any other file contents. It does not descend into candidates, so
an embedded extension folder cannot become a second import.

Linked root ancestry is refused. Within the tree, links and special entries
are skipped and reported. The existing `AefFolder.KindOf` classifier supplies
entry types, including its documented platform fallback. Enumeration errors,
depth omissions, and exceeded entry/run limits appear in `Issues`; any issue
makes `Complete` false. Cancellation throws. Missing or invalid roots are
errors, not complete empty scans.

`Complete` describes discovery coverage only; it never means a candidate is
valid or accepted. Returned lists are immutable and ordinally sorted. Which
candidates fit a truncated scan depends on filesystem enumeration order.
Entry counting includes files and directories; detecting that a bound was
exceeded can enumerate one additional entry without inspecting it. Discovery
is not an atomic filesystem snapshot: ingestion must copy and verify the
staged contents before publication. Source ownership must prevent hostile
concurrent path replacement. HTTP clients must not choose arbitrary local
source roots or receive local candidate paths.

## Remaining lifecycle integration

The next ingestion slices will copy discovered/uploaded evidence into staging
under file-count, byte, and request limits; verify the staged snapshot with
the existing AEF verifier; and publish accepted runs atomically. Invalid,
unsealed, or interrupted imports must never become query-visible accepted
evidence. Duplicate handling and explicit recovery will operate on these
same directories. Those operations are not implemented by `BeginStage`.

Sealed evidence files remain authoritative. The later SQLite index is
derived and rebuildable; it is not a prerequisite for ingestion ownership.
