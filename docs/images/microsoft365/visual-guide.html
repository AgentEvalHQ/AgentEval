EXPERIMENTAL

AgentEval and Microsoft 365

Evaluate Microsoft 365 Copilot and declarative agents over Work IQ A2A 1.0: from code, from the CLI, or with the tester demo.

Status. Built and tested offline; nobody has run it on a live tenant yet, so the first live runs are its validation. Use a non-production tenant and test user: the agent can read and write that user's data.

How it fits together

Every turn either completes with an answer or ends with a typed outcome. Only a completed turn is graded; a turn with several answer candidates and none selected is NOT MEASURED, never a guess.

Pick your path

Microsoft365AgentFactory.BuildLive(config, iUnderstandLiveSideEffects: true)

Set up a tenant in six steps

Each step, who does it, and what a failure means: Connect to a Microsoft 365 tenant.

  1. 1
    Enable Work IQ
    A Global Administrator, once per tenant.
  2. 2
    Billing plan
    Put the test user in a usage-based billing plan. Work IQ calls are billed as Copilot Credits.
  3. 3
    Register an app
    Single tenant, a public client: Allow public client flows = Yes.
  4. 4
    Permission + consent
    Delegated WorkIQAgent.Ask, then Grant admin consent.
  5. 5
    Device-code sign-in
    Make sure Conditional Access allows it for the test user.
  6. 6
    Test the connection
    Write workiq.json and run the readiness check. It sends no prompt.

What you get

Readiness report

readiness.md and readiness.json: each stage, what it proves, what to do when it fails.

Trace and issues

trace.jsonl and issues.jsonl: every event and problem, with the cause and who can fix it.

Honest verdicts

PASS, FAIL, NOT MEASURED or ERROR. A turn that did not complete is never graded.

Sealed AEF run

The house evidence record; agenteval aef verify checks it.

One run folder

The demo keeps all of it in one folder, zipped with --zip, to send back.
