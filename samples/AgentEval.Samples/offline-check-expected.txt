# What every sample in the menu must exit with when it runs OFFLINE: no model provider configured,
# non-interactive, stdin closed. `dotnet run --project samples/AgentEval.Samples -- --offline-check`
# runs each sample in its own process and compares its exit code with this table (CI does too:
# .github/workflows/gatekeeper-offline-samples.yml). It strips every provider variable first, so it is free.
#
# Key: the sample's stable id, its class name. `--list-samples` prints every id beside its menu label.
# It is not the menu number, which shifts when a sample is added.
#
# Exit codes: 0 completed (no failed check, warning or skip recorded), 1 a check the sample makes failed,
# 10 a quality score below its threshold (WARN), 11 not measured (a provider, a key or a dataset is
# missing). 3 (the sample threw) and a hang are never expected: they fail the check.
#
# A sample that needs a model expects 11. A sample that runs offline expects its real verdict, normally 0.
# A sample added to the menu without a row here fails the check, and so does a row with no sample.
